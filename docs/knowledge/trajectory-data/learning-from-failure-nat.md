# Learning From Failure: Integrating Negative Examples when Fine-tuning Large Language Models as Agents

- **Source:** https://arxiv.org/html/2402.11651
- **Authors / org:** Renxi Wang, Haonan Li, Xudong Han, Yixuan Zhang, Timothy Baldwin (LibrAI, MBZUAI, University of Melbourne)
- **Date:** 2024-02 (arXiv v2 dated 2024-04-16)
- **Type:** paper
- **Read:** full text

## Summary

Standard practice for agent fine-tuning is to collect trajectories from a stronger model and discard those that fail. The paper asks whether failed trajectories can be used instead of thrown away, and proposes negative-aware training (NAT).

A teacher (GPT-3.5) generates tool-using trajectories at several temperatures. Each is labelled positive or negative by comparing its final answer with the ground truth. Before training, a short marker is appended to the task query: one string for trajectories that succeeded, a different one for those that failed. The student (Llama-2-chat 7B or 13B) is trained on both kinds with loss on the model-generated text only. At inference the "success" marker is always used.

Tasks are math word problems with a calculator tool, and multi-hop question answering with a search tool. With 2k positive trajectories, average math accuracy for the 7B model rose from 55.90 (positives only) to 64.64 with NAT. Mixing in failures without the marker also helped somewhat but less than NAT in every math setting, and it increased action errors (10.47%), while NAT reduced them (7.90%). On StrategyQA accuracy rose from 55.40 to 65.80.

Two conditions limit the benefit. Quantity: the gain shrinks as the number of positives grows; with 5k positives the 13B model improved only from 70.76 to 71.28. Quality: failures from the strong teacher helped, but failures generated by a weak fine-tuned 7B model hurt (for example -3.16 points at 2k positives). The content of the marker did not matter; arbitrary tokens worked as well as meaningful ones. Analysis suggests failures mainly improve the reasoning text, not tool use.

The tasks are short question-answering episodes, not long coding sessions, and the method needs ground truth to label outcomes.

## Key points

- Failed teacher trajectories carry usable signal if the model is told which ones failed.
- Unmarked failures mixed into training raise action error rates.
- The benefit is largest when successful data is scarce and fades as it grows.
- Failures from a weak model are harmful; only near-miss failures from a strong teacher helped.
- Inference always conditions on the success marker.

## Relevance to JacKnife

(Our interpretation.)

- Early on, when verified Jac trajectories are few, failed teacher runs can be added with an outcome tag in the system or task message. Drop them once positive data is plentiful.
- Never mix untagged failures into training, and do not use the 9B student's own failures as negatives.
- This is whole-trajectory failure. It is different from recovery data (a trajectory that hits an error and then fixes it and succeeds), which is a positive example and should be kept; no source in this folder measures the value of recovery segments directly.
- The evidence is from short tool-use tasks; transfer to multi-step coding is an assumption.
