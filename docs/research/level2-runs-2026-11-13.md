## Findings

- **Browser feedback produced the only pass.** The model submitted, was told "expect Buy milk: text not on the page", edited the page, and passed (13 turns). In another run it got the same message for the reload action, edited the server, and failed again.
- **The guide stopped the runaway replies and made everything else worse.** With the guide: 0 of 12 runs had a cut-off reply, against 6 of 12 without. But 0 of 12 reached `submit`: the model wrote a more elaborate page (keyboard handlers, element references) and could not get it through the type checker.
- **DRY sampling shows no clear effect** on cut-off replies (2 of 6 runs with, 4 of 6 without).
- **The type checker on browser types is the main wall.** Typical first errors: `Type "HTMLElement" has no attribute "value"`, `Type is Unknown, cannot access attribute "target"`, `Cannot assign KeyboardEvent to parameter 'e' of type MouseEvent`. The model does not know how to read an input's value in a typed way, and the compiler message does not say how.
- **`edit` fails often on `old-not-found`** (15 of 24 runs in rounds 2 and 3 had at least one). After a failed `write` the file on disk is not what the model believes it wrote.
- **The wiring check still fires in every run that reaches `submit`**, and names one missing import at a time.
- **Five failures is reached fast.** Every stalled run ended on the failure count or the same-error rule within 9 to 15 turns, with context under 10,200 tokens. There is no admin yet, so a stall ends the run.

## Harness bugs found by round 2

| Bug | Effect | Fix |
|---|---|---|
| One variable used both as a list and as a counter in the session loop | 5 of 12 runs crashed when the same error came twice | Renamed |
| A call was refused as a repeat of an earlier failed call even after a file had changed | `submit` was refused after the model had fixed the import; 2 runs lost | Only failures since the last file change count |

## What this points to

1. A failed `write` leaves the model with a wrong picture of the file. Either a failed write is not saved, or the result says what is on disk. To decide.
2. The wiring check should list every missing name in one message.
3. The model needs the typed form of the few browser events it uses (input change, click, key press). A short, targeted note beats the full guide, which costs 6,700 tokens and pulls the model toward a larger page. This is input for decisions 8 and 9.
4. Level 2 is beyond what the model does alone. The admin tier (0010a) is the next piece that changes the pass rate; the checks and feedback are already catching the failures.
