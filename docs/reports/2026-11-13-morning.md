## 3. Results

Details: [first runs](../research/first-runs-2026-11-12.md), [level 2 runs](../research/level2-runs-2026-11-13.md).

| Level | Runs | Browser pass | Note |
|---|---|---|---|
| 1 | 5 | 4 | The one failure was before the wiring check existed. |
| 2, first state | 6 | 0 | |
| 2, with browser feedback and repeat handling, bugs fixed | 12 | 1 | 3 runs each of: baseline, DRY sampling, guide in the card, both. |

What the runs showed:

1. **The wiring check is needed in every run.** Without a hint the model never adds the entry-file import on its own; `jac check` stays clean and the app returns 405.
2. **Browser feedback on `submit` works.** It produced the only level-2 pass.
3. **Typed browser events are the main wall at level 2.** The model cannot get an input's value past the type checker.
4. **Putting the full guide in the card did not help**: it stopped the runaway replies but no run with it reached `submit` (0 of 12).
5. **Failed `write` followed by failed `edit`** is the most common loop (15 of 24 runs).
6. Two bugs of mine made one batch of 12 invalid. Both fixed; the batch was run again.
